# Rollarr Controller

Контроллер сезонных раздач с безопасным отказом, использующий только Sonarr, Prowlarr (через Sonarr) и qBittorrent.

[Полная английская версия / Full English README](README.md)

## Установка

Образ контейнера: `ghcr.io/vladido/rollarr-controller:latest` ([GHCR](https://github.com/vladido/rollarr-controller/pkgs/container/rollarr-controller)).

Для фиксированной версии закрепите доступный тег `sha-<commit>` или digest; перед обновлением сохраните предыдущий digest.

Создайте отдельный каталог установки и сохраните следующий YAML как `compose.yaml` (полный пример из [compose.example.yaml](compose.example.yaml)):

```yaml
services:
  rollarr-controller:
    image: ghcr.io/vladido/rollarr-controller:latest
    container_name: rollarr-controller
    restart: unless-stopped
    env_file:
      - ./config/rollarr-controller/controller.env
    volumes:
      - ./config/rollarr-controller/state:/state
    expose:
      - "8080"
    networks:
      - servarr

networks:
  servarr:
    external: true
    name: ${SERVARR_NETWORK:-servarr}
```

Нужны Docker с Compose, работающие Sonarr и qBittorrent, настроенные в Sonarr индексаторы Prowlarr и download client. Сериал и сезон должны уже существовать и отслеживаться в Sonarr. Rollarr не предоставляет собственный веб-интерфейс; для панели используйте Servarr Tools UI.

1. Сохраните Compose из примера выше; создайте каталоги и закрытый env-файл.
2. Создайте `config/rollarr-controller/controller.env` с переменными из раздела ниже, правами `0600` и `ROLLARR_DRY_RUN=true`.
3. Создайте `config/rollarr-controller/state` и предоставьте UID/GID `1000:1000` запись: контейнер работает от этого пользователя. Не открывайте каталог всем пользователям.
4. Подключитесь к внешней сети Docker `servarr`, в которой доступны Sonarr и qBittorrent. Измените имя через `SERVARR_NETWORK` при необходимости; сеть должна уже существовать.

```sh
mkdir -p config/rollarr-controller/state
umask 077
touch config/rollarr-controller/controller.env
chmod 600 config/rollarr-controller/controller.env
sudo chown 1000:1000 config/rollarr-controller/state
sudo chmod 700 config/rollarr-controller/state
```

Заполните env-файл значениями из следующего раздела до запуска. Sonarr/qBittorrent должны быть подключены к той же сети; создание пустой сети не подключает существующие контейнеры автоматически. При необходимости создайте её `docker network create servarr`. `SERVARR_NETWORK` задаётся через `.env` Compose или окружение оболочки, не через `controller.env`. Порт `8080` не публикуется на хосте.

### Обязательные переменные окружения

```text
SONARR_URL=http://sonarr:8989
SONARR_API_KEY=...
QBIT_URL=http://qbittorrent:8080
QBIT_API_KEY=...
ROLLARR_DRY_RUN=true
```

Необязательные: `ROLLARR_POLL_INTERVAL=900`, `ROLLARR_MIN_SEEDERS=1`,
`ROLLARR_MAX_BYTES_PER_EPISODE=12000000000`, `ROLLARR_CATEGORY=tv-sonarr`,
`ROLLARR_STATE_DIR=/state`, `ROLLARR_HEALTH_PORT=8080` и `SERVARR_TOOLS_TOKEN`. Если
`SERVARR_TOOLS_TOKEN` не задан, ручной запуск отключён и `POST /v1/runs`
недоступен. Держите порт API только в доверенной внутренней сети контейнеров.

Явные автоматические цели задаются как
`ROLLARR_TARGETS=tvdb_id:season:tracker:topic,...` ограничивает выбор раздач
для уже существующего отслеживаемого сериала указанной темой. Rollarr не создаёт
сериалы: удалённые или неотслеживаемые сериалы пропускаются. Добавление и
мониторинг управляются в Sonarr; прежние параметры `ROLLARR_ROOT_FOLDER` и
`ROLLARR_QUALITY_PROFILE_ID` не дают разрешения на автоматическое создание.


### Запуск и безопасное включение live

Загрузите готовый образ и запустите сервис:

```sh
docker compose config --quiet
docker compose pull
docker compose up -d
docker compose logs --tail 100 rollarr-controller
```

При запуске сразу начинается плановый цикл; интервал между циклами — не менее 60 секунд. Проверьте завершение цикла, отклонённые кандидаты и предложения в аудите до включения live. Для live установите `ROLLARR_DRY_RUN=false`, затем пересоздайте только сервис Rollarr. Ручной запуск через панель использует настроенный режим, не переключая dry-run/live.

**Авторизация qBittorrent:** Rollarr использует схему Bearer в заголовке `Authorization`, передавая `QBIT_API_KEY`; вход по имени пользователя и паролю не реализован. Стандартный Web API qBittorrent использует вход с сессией, поэтому до запуска нужен совместимый endpoint, принимающий Bearer. Не подставляйте пароль вместо API-ключа.


## Принцип работы

- Получает из Sonarr отслеживаемые вышедшие эпизоды Wanted; явно отслеживаемые темы также включают отсутствующие отслеживаемые эпизоды без даты выхода в первоисточнике.
- Запускает в Sonarr поиск с привязкой к сериалу и сезону и скачивает настоящие метаданные `.torrent`.
- Проверяет точный состав файлов и сезона, каноническое название или псевдоним, год выхода сезона или предшествующий год производства, число сидов, размер, идентичность темы, монотонное расширение конечной точки и ранее не встречавшийся infohash. Коллизии с тем же названием из более старых сезонов отклоняются.
- Перед отправкой заменяет проверенное составное название трекера каноническим названием сериала из Sonarr, затем требует, чтобы парсер Sonarr подтвердил те же сериал, сезон и набор эпизодов до скачивания или захвата кандидата.
- Считает предупреждение Sonarr о нулевом размере при неизвестной продолжительности лишь предварительным; Rollarr всё равно проверяет состав скачанных метаданных и суммарный размер в байтах перед захватом.
- При одинаково полных наборах сначала ранжирует по весу качества Sonarr и оценке Custom Format, затем по числу сидов или размеру. Принятая тема, не охватывающая первый эпизод Wanted, не блокирует проверенную расширенную тему.
- Отправляет первоначальные захваты и дальнейшие обновления темы через Sonarr. Поэтому расширенный набор может скачиваться полностью; повторное использование трафика не гарантируется.
- Записывает конечную точку темы и хеш в SQLite только после того, как Sonarr отметит каждый эпизод из торрента как импортированный (`hasFile=true`).
- Сохраняет отправленные запросы как ожидающие и сверяет их после импорта, даже если сериал исчез из Wanted. При миграции старые запросы восстанавливаются только по соответствующим записям аудита и проверенным сохранённым метаданным.

По умолчанию действует `ROLLARR_DRY_RUN=true`. Здоровый контейнер означает лишь успешный запуск; готовность к эксплуатации требует реального обновления с добавлением эпизодов без удаления старых и штатного импорта в Sonarr.

## API наблюдения и управления

HTTP-сервер стандартной библиотеки слушает `ROLLARR_HEALTH_PORT` (по умолчанию `8080`).
В примере Compose он доступен только в сети Compose, но не на хосте.

- `GET /live` — проверка живости процесса, независимо от результата цикла.
- `GET /health` сохраняет прежний формат ответа о состоянии.
- `GET /v1/health` сообщает состояние, сервис/версию, настроенный режим dry-run,
  состояние очереди и выполнения, возможности и метаданные последнего запуска.
- `GET /v1/status` сообщает те же метаданные выполнения и конфигурации, не
  меняя свой HTTP-статус после неудачного цикла.
- `GET /v1/audit?limit=N` возвращает последние записи аудита первыми, только из разрешённых полей. `N`
  ограничивается диапазоном `1..200`; некорректная завершающая строка JSONL игнорируется. Данные торрентов,
  хеши, темы трекеров, URL и учётные данные не возвращаются.
- `POST /v1/runs` ставит в очередь один ручной запуск и возвращает `202` либо `409`, если запуск
  уже стоит в очереди. Требует серверный `SERVARR_TOOLS_TOKEN` в заголовке `Authorization` со схемой Bearer и
  принимает необязательный заголовок `Idempotency-Key`. Повторное использование ключа в
  ограниченном пятиминутном кэше возвращает исходный запуск и его текущий статус
  (`queued`, `running`, `completed` или `failed`), не начиная повторное сканирование.
  Сканирования движка выполняет только один рабочий процесс, общий с плановыми запусками.

Если последний цикл завершился ошибкой, обе конечные точки проверки состояния возвращают `503`, даже если
предыдущий цикл был успешным. Сведения об ошибке ограничены классом исключения.



## Диагностика, обновление и резервная копия

- `/live` отвечает, но `/v1/health` возвращает `503`: процесс работает, последний цикл завершился ошибкой. Проверьте `last_run`, `last_error` и доступность поиска Sonarr/Prowlarr; старый успешный цикл не отменяет новой ошибки.
- Кандидат отклонён: проверьте причину аудита, состав `.torrent`, отслеживание эпизодов, качество и наличие сидов. Не отключайте проверки ради принятия неоднозначной раздачи.
- `waiting_for_import`: захват уже отправлен; подтверждение ожидает `hasFile=true` у всех эпизодов. Сверьте очередь и импорт Sonarr, не удаляя раздачу ради повторной попытки.
- Wanted читается одной страницей с `pageSize=1000`; каталог большей величины требует отдельной оценки полноты.

Для обновления сохраните конфигурацию и состояние, включите dry-run, выполните `docker compose pull` и `docker compose up -d`, затем при необходимости скачайте [scripts/check-after-update.sh](scripts/check-after-update.sh) и выполните `sh check-after-update.sh`. Скрипт проверяет контейнер `rollarr-controller` и завершённый успешный цикл, но не подтверждает правильность импорта медиа. Для отката используйте заранее сохранённый тег/дайджест образа, не удаляя состояние.

Сохраняйте защищённый env-файл и весь каталог состояния: `ledger.db`, `audit.jsonl` и сохранённые метаданные. Для согласованной копии SQLite остановите только Rollarr на время копирования либо используйте SQLite backup API. Потеря ledger означает потерю учёта принятых тем, известных хешей и ожидающих импортов. Не публикуйте эти данные в Git.

## Для разработчиков: необязательная сборка из исходников

Для разработки с Git и Docker соберите локальный образ и задайте `image` в локальной копии Compose как `rollarr-controller:dev`. Требования к конфигурации, секретам и сети из предыдущих разделов действуют и при разработке.

```sh
git clone https://github.com/vladido/rollarr-controller.git
cd rollarr-controller
docker build -t rollarr-controller:dev .
```
